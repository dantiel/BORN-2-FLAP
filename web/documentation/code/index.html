The four layers and how they fit together.

Code Overview

BORN2FLAP is a real-time ornithopter flight simulator. It is four layers in one process, and each layer has a clear job.

The four layers

1. Haskell MathCore (MathCore/)

The canonical physics - pure, total, tested. All aerodynamics, kinematics, servo/actuator modelling, control mixing and stabilisation live here. It is compiled to born2flap_math.dll and called through a stable C ABI. Haskell is the single source of truth; the game never re-implements physics.

2. Native C/C++ (Native/)

The ABI boundary. born2flap_math.h declares the C structs and functions; born2flap_math_bridge.cpp loads and wraps the Haskell DLL. RC transmitter and desktop input headers live here too.

3. Unreal Engine 5 (Unreal/Born2Flap/)

The game: the flight pawn (physics bridge + audio + replay), the game mode (level/menu lifecycle), the fullscreen menu, the UMG renderer, the audio synthesiser, and the world/water/weather systems.

4. Brain (Brain/)

A Ruby framework that turns a declarative tree (UMGHAML) into semantic UI actions. It owns menu/views/RC panels and their text; Unreal renders them.

Data flow

Mouse/RC input -> ABorn2FlapFlightPawn -> born2flap_math.dll (Haskell) -> forces/moments -> Unreal physics -> wing mesh deformation + audio.

Auto-generation

The API index and the per-language symbol lists are generated by Tools/gen_code_reference.py into web/_code_ref/*.md. The narrative guides on these pages are written by hand and maintained alongside the code.

Related projects

  • OrniFlight — the web configurator whose ONDAS/servo/mixer/PID logic and servo-efficiency data feed the in-game hangar and tuning.
  • PteronautOS — the open firmware/OS; the flapping waveform and mixer are faithful ports of it (see the waveform guide).
